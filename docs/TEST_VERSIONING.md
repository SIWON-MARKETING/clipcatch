# ClipCatch 테스트 버전 관리 기준

승인일: 2026-11-26. 정식 버전과 테스트 버전 모두 GitHub에서 추적한다.

## 원칙

1. 모든 테스트 빌드는 정확한 소스 커밋에 대응하는 **고유 버전**을 갖는다(예: `2.0.1-test.9`, `2.0.1-test.10`). 실행파일의 `go version -m` 내 `vcs.revision`으로 빌드 원본을 확인한다.
2. 테스트 버전별 GitHub 브랜치를 고정해 구분한다: `test/clipcatch-preview-<버전>`. 각 빌드를 만든 뒤에는 그 브랜치의 해당 커밋 해시를 테스트 기록에 적는다. 과거 테스트 브랜치를 새 버전으로 덮어쓰지 않는다.
3. 테스트 로그에는 요구사항, 변경 파일, 확인한 항목/실패/미실행, 빌드 명령/실행환경, ZIP/EXE SHA-256, 이전 버전 복구 기준을 남긴다. **검증되지 않은 항목을 통과로 표시하지 않는다.**
4. 배포용 테스트 ZIP은 해당 소스 커밋에서 빌드해야 한다. GitHub Actions 보관 기간은 영구 보존이 아니므로 필요한 테스트 실행파일은 GitHub prerelease 또는 별도 승인된 보관처에 체크섬과 함께 저장한다. Git 브랜치만 생성한 상태를 실행파일 보관 완료로 부르지 않는다.
5. `main` 정식 빌드와 테스트 브랜치를 분리한다. 운영 실행파일, 설치 경로, 데이터 폴더, 포트, 업데이트 피드, 브라우저 확장 페어링을 임의로 변경하지 않는다. 정식 버전 반영/배포는 별도 승인 후 검증한다.
6. 사용자 콘텐츠/영상 파일, 계정/토큰/쿠키, PC 설치 폰트는 GitHub에 올리지 않는다. 일반 테스트 증거는 민감 정보를 제거하고 기록한다.
